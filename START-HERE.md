# START HERE - ExitFlow Documentation Pack

## Project Introduction
**Project Name:** ExitFlow  
**Full Title:** ExitFlow – STPI Exit Checklist & Document Tracker  

ExitFlow is a web-based prototype designed to help users organize and track an illustrative STPI (Software Technology Parks of India) exit-related workflow. It manages structured stages, document checklists, status tracking, deadlines, progress monitoring, and activity logs. 

*Disclaimer: This is an independent academic prototype developed as supplementary work for a B.Tech internship report. It is NOT an official EY product, STPI application, government portal, or production-ready compliance solution.*

## Purpose of the Documentation Pack
This documentation suite serves as the complete blueprint for developing the ExitFlow MVP (Minimum Viable Product). It is designed to guide the development process, provide context for AI coding assistants, and serve as the official project documentation for academic reporting.

## Included Documents
1. **START-HERE.md** - This index file.
2. **PRD.md** - Product Requirements Document detailing the scope, features, and user journeys.
3. **architecture.md** - Technical architecture, database schema, and API design.
4. **phases.md** - Step-by-step implementation roadmap (10-14 days).
5. **document-catalogue.md** - Illustrative checklist items for the six workflow stages.
6. **style-guide.md** - UI/UX guidelines, color palette, and layout structures.
7. **README.md** - Standard project README with setup and execution instructions.
8. **memory.md** - Context document for AI coding assistants tracking decisions and progress.

## Recommended Reading Order
For a complete understanding of the project, please read the documents in the following order:
1. `PRD.md` (Understand the "Why" and "What")
2. `architecture.md` (Understand the "How")
3. `document-catalogue.md` (Understand the domain data)
4. `style-guide.md` (Understand the visual language)
5. `phases.md` (Understand the execution plan)
6. `README.md` (Developer onboarding)
7. `memory.md` (Ongoing reference)

## How to Use These Documents During Development
- Treat `PRD.md` as the source of truth for features. Do not add features outside its scope.
- Use `architecture.md` for naming conventions, schema designs, and API routes.
- Follow `phases.md` strictly. Complete Phase N before starting Phase N+1.
- Provide `memory.md` to any AI assistant (like Gemini or Copilot) at the start of a session to establish context.
